# TradingAgent Product Design

Evalúa cada página como una tarea del operador. Consulta primero Graphify y el read model real; no inventes estados ni capacidades para completar el diseño.

Antes de cambiar una pantalla identifica: qué debe saberse primero, qué necesita atención, qué acción es frecuente, qué detalle puede expandirse y qué evidencia falta para decidir. Verifica el flujo completo con datos disponibles, no sólo componentes aislados.

- Dashboard: estado comprensible en cinco segundos; actividad y bloqueos con contexto. Distingue recopilar datos de estar autorizado para operar.
- Experimentos: tres carteras comparables con riesgo fijo; Shadow frente a Paper separado, siguiente perfil como intención condicionada y no promesa de ejecución.
- Operaciones: inventario abierto primero, comisiones/conciliación pendientes visibles, procedencia y detalle auditable. Cero operaciones no significa fallo del producto.
- Mercado/Kronos: actualidad y calidad antes de dirección; consenso/contradicciones junto al forecast, incertidumbre y muestra visibles.
- Sol: acceso consistente, ejemplos útiles, respuestas estructuradas y presupuesto visible. La evaluación contextual nunca concede autoridad ni inventa confianza.
- Research: pipeline basado en estados registrados, conclusiones y rechazos, prueba final sellada y ausencia de promoción automática. No contabilices etapas desconocidas como superadas.
- Reportes: comparaciones con unidad coherente, costes y muestra; exportación de evidencia sin secretos.
- Configuración: estado protegido de sólo lectura y procedimiento externo para acciones sensibles. No añadas botones para limpiar emergencia, autorizar o alterar riesgo sin un alcance explícito diferente.

Reduce carga cognitiva sin esconder restricciones. Acciones frecuentes de lectura deben ser fáciles; las sensibles conservan su mecanismo protegido existente. No inventes aprobaciones para consultas reversibles. Evalúa teclado, móvil, error y desconexión. Documenta mejoras, evidencia de pruebas y pendientes humanos.
